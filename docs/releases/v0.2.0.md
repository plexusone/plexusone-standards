# v0.2.0 — 2026-08-29

`plexusone-standards` becomes a multi-domain repo: what was a single-purpose
design-tokens repo (`plexusone-design-system`) is now the front door for
PlexusOne's own instances of its standards specs, organized by domain.

## Highlights

- **Domain restructure.** `design-system.json`, `package.json`, `agents/`,
  `examples/`, `loops/`, and `llm-context.md` moved into `design-system/`
  as a group. The root README is now a cross-domain index rather than a
  single-purpose description.
- **`api/rest/` domain, new.** The `plexusone-rest` REST API style
  profile — 17 rules across naming, errors, pagination, SystemForge
  authentication and scopes, `prn://` cross-product references, run
  resources, streaming, and versioning — with three conformance levels
  (minimum/standard/exemplary). Ships alongside its generated Spectral
  ruleset, LLM evaluation rubric, and human-readable guide.
- **`resourceref/` domain, new.** The real `prn` resource-reference scheme
  instance: registered authorities, tenant-scoped and ecosystem-artifact
  path shapes, `resourceType` registries for `dashforge` and `actionforge`,
  and the `@version`/`@alias` suffix grammar. It's a small Go module in
  its own right — `go test ./...` loads the profile through
  [resourceref](https://github.com/plexusone/resourceref)'s scheme engine
  and checks it against real reference examples, not just that the JSON
  parses.
- **`naming/` domain, new.** The module and product naming-conventions
  standard — when to use `omni*`, `*forge`, `*-core`, or a plain
  functional name — cross-referenced directly against the `prn` profile
  and the API style guide's scope grammar rather than restated.

## Fixed

While proving the `plexusone-rest` profile actually functions as a
linter (not just documentation), linting an `api-style-spec` exemplar
surfaced a real bug: the `PX-003` URL-pattern rule had an
OpenAI-compatibility carve-out regex that accepted *any* bare
`/v{N}/...` path, silently defeating the rule it was attached to.
Fixed and re-verified: the same exemplar now correctly fails on an
unversioned path.
